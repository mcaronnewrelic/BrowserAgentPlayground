Install the browser agent

First, get it
on the page.

Everything the other pages show starts with one script that loads before anything else on the page. There are three ways to add it, and the right one depends on how your site is built.

See what this page loaded → Compare the three ways
Load it first The agent only sees what happens after it loads. Put it as close to the top of <head> as you can, right after <meta charset>. Loaded later, it misses early errors, slow resources and the page's first paint. 
<head>
  <meta charset="utf-8">
  <!-- 1. The browser agent, first -->
  <script>
    NREUM.init = { /* what to collect */ }
    NREUM.info = { /* where to send it */ }
    NREUM.loader_config = { /* account IDs */ }
    /* the agent loader */
  </script>
  <!-- 2. Everything else -->
  <link rel="stylesheet" href="app.css">
  <script src="app.js"></script>
</head>

Everyone shares one New Relic account, so your page views are tagged as demoUser and demoCode custom attributes (your name is also set as your end-user ID via setUserId()). The query at the bottom of this page finds the page views from your own visits.

Learn it / Three ways to install

Pick your method

All three load the same agent with the same three pieces of configuration. They differ in who puts the script on the page and how it gets updated. The one this page used is outlined.

Which one fits?

Start from how your site is built

  1. A server renders your HTML and already runs a New Relic APM agent (for example Java, .NET, PHP, Python, Ruby, Go or Node.js): let the APM agent add it. Nothing to paste, and the browser data links to the server it came from. New Relic recommends this for apps that aren't single-page apps.
  2. You build the front end with a bundler and npm (React, Vue, Angular, Next.js and so on): use the npm package. The agent ships inside your own code, versioned with it.
  3. Anything else, like static pages, a CMS, or a site you can only edit as HTML: paste the snippet into each page's <head>.

To start any of them in New Relic, go to Integrations & Agents, then Browser and mobile, then Browser monitoring, and follow the steps. For an app that already exists, its snippet is under Browser > your app > Settings > Application settings.

Copy and paste
This page

A script block in <head>

Use it when you control the HTML but have no build step and no APM agent.

<meta charset="utf-8">
<script type="text/javascript">
;window.NREUM||(NREUM={});
NREUM.init={…};
NREUM.loader_config={accountID:"…", …};
NREUM.info={beacon:"bam.nr-data.net",
  licenseKey:"NRJS-…", applicationID:"…"};
/* the agent loader, minified */
</script>
  • You paste it into every page, so updates mean re-pasting. When you change Application settings in New Relic, re-copy the snippet: it doesn't update itself.
  • The NRJS- key is a browser key. It's meant to be public: it can only send data, not read it.
  • On this site, GitHub Pages uses this method, split into three files so it's edited once: nr-init.js (init), nr-config.js (info and loader_config) and nr-agent.js (the loader).
Injected by APM
This page

The server adds it for you

Use it when your HTML comes from a server that a New Relic APM agent already monitors.

// Node.js: the APM agent loads before anything else
const newrelic = require('newrelic')

// For each page: a <script> tag with the agent and its settings
const header = newrelic.getBrowserTimingHeader()
html = html.replace('<meta charset="utf-8">',
  '<meta charset="utf-8">' + header)
  • The browser app is created and linked to the APM app for you, and restarting the APM agent picks up the latest browser agent.
  • Some APM agents insert it into HTML responses automatically. With Node.js you call getBrowserTimingHeader() yourself, as above.
  • Don't also paste the snippet into the same pages. Two agents on one page double-count everything.
  • On this site, the Node server in backend/ (and the Docker image) uses this method. backend/pages.js swaps the copy/paste block for the APM agent's header on every page it serves.
npm package

@newrelic/browser-agent in your bundle

Use it when your front end is built from source with npm and a bundler.

// The very first lines your app runs
import { BrowserAgent } from '@newrelic/browser-agent/loaders/browser-agent'

// Copy these from the copy/paste snippet: NREUM.init, NREUM.info, NREUM.loader_config
const options = { init: { … }, info: { … }, loader_config: { … } }

new BrowserAgent(options) // starts immediately
  • The agent version is pinned in your package.json, so it changes only when you upgrade it, and it goes through your own review and tests.
  • Put it first in your entry file. Imported later, or lazily, it misses everything that happens before it starts.
  • To keep your bundle smaller, the Agent loader lets you include only the features you use instead of all of them.
The same three settings, whichever method

init, info and loader_config

NREUM.init
What to collectTurns features on and off and tunes them: session replay sampling, privacy masking, distributed tracing, marks and measures. This is the part you edit most.
NREUM.info
Where to send itThe collector address (beacon), the browser key and the application ID. It decides which app in which account the data lands in.
NREUM.loader_config
Who it belongs toAccount and agent IDs, used to connect browser data to backend traces. Change it only by re-copying it from New Relic.
Learn it / How data reaches New Relic

Why it takes a minute

Every demo page says to allow a minute before you look for your data. This is why, and where each kind of data shows up when it gets there.

Batches, not live

The agent sends data in batches

Nothing is sent the moment you click. The agent collects data in the browser and sends it in batches, most of it about every 30 seconds, and once more when you leave the page. New Relic then needs a few more seconds to process it. So a minute after you do something, it's usually there.

Some data waits for an ending, by design:

  • Core Web Vitals: CLS and INP are final only when you leave the page view, so that's when they're sent.
  • WebSockets: one event per connection, sent after it closes.
  • Session replay: sent on its own schedule, separate from everything else.
Still nothing after a minute?

Check in this order

  1. Is the agent on the page? The badge at the top of each page says "Browser agent detected" when it is.
  2. Is it sending? The requests panel above should list requests to New Relic. If not, look for an ad blocker or a Content Security Policy.
  3. Is the feature on? Each page's Before you start box lists what it needs, and where that setting lives.
  4. Are you looking at the right data? Check the session code in the query, and that the time window (SINCE) covers when you clicked.

Reading the queries on these pages

          
Every demo page ends with queries like the one above, written in NRQL, New Relic's query language. They all follow the same shape, so once you can read one, you can read them all.

          


SELECT timestamp, actionName
FROM PageAction
WHERE demoCode = 'NR-XXXX'
SINCE 1 hour ago
LIMIT 100

            

              
FROM PageAction
The event type: which kind of record to look in. Each feature writes its own, such as PageView, JavaScriptError or Log.

              
SELECT timestamp, actionName
The attributes (columns) to show. SELECT * shows every attribute, which is a good way to explore an event type you haven't seen before. SELECT count(*) counts rows instead of listing them.

              
WHERE demoCode = '…'
Keeps only the rows you made. Every page tags your data with your session code, because everyone shares this account.

              
SINCE 1 hour ago
The time window. With no SINCE, a query looks at the last hour.

              
FACET … / LIMIT 100
FACET groups rows by an attribute, like a pivot table. LIMIT caps how many rows come back.
