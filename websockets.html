New Relic browser WebSockets

One socket.
One event.

Every AJAX call gets its own event. A WebSocket can stay open for an hour and carry thousands of messages, so the agent keeps a running tally and sends a single WebSocket event when the connection closes.

Open a socket → Jump to the query
Off by default WebSocket tracking is opt-in. This page turns it on with init.web_sockets.enabled before the agent loads, and the agent then wraps window.WebSocket. Sockets made before that, or on pages without the setting, are never counted. 
// Turn it on before the agent loads
NREUM.init.web_sockets = { enabled: true }

const ws = new WebSocket('wss://echo.websocket.org')
ws.send('hello')     // sendCount, sendBytes
// messages arrive  // messageCount, messageBytes
ws.close(1000)      // closeCode, connectedDuration
// -> one WebSocket event for the whole connection

Everyone shares one New Relic account, so your clicks are tagged as demoUser and demoCode custom attributes (your name is also set as your end-user ID via setUserId()). The agent copies them onto every WebSocket and JavaScriptError event you cause below.

1 · A connection you drive

Open it, use it, close it

Connect, send as much or as little as you like, then close it. Each send comes back as a message, so it adds to both sides of the tally. Text counts as string both ways. Binary goes out as ArrayBuffer but comes back as Blob, because a socket's binaryType is blob unless you change it.

2 · Close with your own code

close(4000, reason)

Apps can close with 1000 or anything from 3000 to 4999, so a code you choose can tell you why sockets end. The agent records what the close event reports, which comes from the server's reply: the code always comes back, but the reason only if the server repeats it. Otherwise closeReason stays unknown.

ws.close(4000, 'Demo: user signed out')
// closeCode 4000, closeWasClean true

4 · An error in a message handler

Only addEventListener is watched

Both buttons open a socket whose message handler throws. The agent wraps handlers you add with addEventListener: when one throws, it marks the socket hasErrors and tags the JavaScriptError with the socket's socketId. A handler assigned to ws.onmessage isn't wrapped, so its error arrives with no link to the socket.

ws.addEventListener('message', () => {
  throw new Error('Demo: bad message')
})
WebSocket: hasErrors true. JavaScriptError: has socketId. 
ws.onmessage = () => {
  throw new Error('Demo: bad message')
}
WebSocket: no hasErrors. JavaScriptError: no socketId.

5 · Walk away with it open

The page closes it for you

Lots of sockets are never closed by the app: people just leave. When the page unloads, the agent records every socket that's still open with close code 1001, reason Page navigating away and closeWasClean false. This button opens a socket, sends one message, then reloads the page.

The same sockets, seen by the server

          
The demo backend writes one log per connection when it ends, with what it counted from its side. The page adds your code to the socket's URL (/ws?demoCode=…) so the log can carry it. These logs belong to the backend's APM entity and have no trace.id: a WebSocket upgrade isn't an APM transaction, so it isn't part of a distributed trace.
